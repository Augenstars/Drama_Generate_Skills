# Drama_Generate_Skills
基于自身需求，创作的面向中文短剧、漫剧、名人传记等视频创作的技能工作流，通过初始化项目，固定资产，参考内容生成，图像生成，审阅，视频生成，最后剪辑形成项目。本技能适用于当前主流图像模型
创作内容保存在可阅读、可修改的 Markdown 文件中。你可以只完成文本，在自己的平台生成媒体；也可以配置执行服务，让生产技能在展示预览并取得本次确认后调用接口。

**第一次使用：先安装技能，确定视频模型与完整服务档位，再从“快速开始”复制请求。已有剧本、图片或视频时，可直接进入对应环节。**

## 这套技能能做什么

- **开发故事与改编材料**：从点子、梗概、小说或已有多集剧本进入，形成系列方向、当集目标与集间交接。
- **完成单集五份创作文档**：剧本、视觉设定、分镜、图片提示词、视频提示词各自记录对应的创作事实。
- **准备可直接使用的提示词**：说明人物、空间、动作、镜头、声音和参考素材职责，区分单镜与多镜一次生成。
- **维护跨镜连续性**：把身份、造型、持物、空间与状态变化落进文档，并核对引用、时长、连续性锁与素材编号。
- **按需审查实际结果**：检查文档、图片、视频和成片，定位问题；不合格实图当轮附可复制更正提示词。
- **使用真实素材剪辑**：选择可用区间、安排镜序、字幕与声音，写剪辑单并渲染、测量输出。

本项目基于 [ZenStory AI / drama-skills](https://github.com/zenstory-ai/drama-skills) 开展，并结合实际制作需求调整技能规则、模型适配与使用说明。技能名称与运行说明以当前发布代码为准；原项目的样片、成本、使用规模和测试结果不作为本项目的验证结果。


## 安装与运行条件

### 需要准备什么

| 使用范围 | 运行条件 |
|---|---|
| 对话写作、设定和提示词 | 可读取本地技能与项目文件的 Agent；本说明以 Codex 为例 |
| 初始化、章节索引、文档检查、Dashboard | Python 3.9 或更新版本 |
| 素材探测、剪辑、渲染和成片测量 | PATH 中可运行的 `ffmpeg`、`ffprobe`；默认字幕路线需要带 libass 的 FFmpeg |
| 可选 Remotion 字幕或画面文字叠层 | Node.js、npm 及剪辑技能所需依赖；普通字幕使用默认路线时不需要这套 Node 依赖 |
| 委托技能实际生成媒体 | 可用供应商账号、匹配的适配器配置与凭据；配置放项目外，凭据由运行环境读取 |

只使用文本阶段不要求配置图片或视频 API，也不要求本地部署扩散模型。真实媒体的生成费用和运行条件取决于你使用的服务；本项目不提供生成额度。

### 在 Agent 中安装

1. 从本项目 GitHub 页面下载代码，或获取包含正式技能的发布包。
   找到包含 `SKILL.md` 的 11 个 `short-drama*` 文件夹，将它们完整复制到下面选择的技能目录。
   保留每个技能已有的 `agents/`、`scripts/`、`references/`、`assets/`，并让 11 个技能文件夹保持同级。
2. 直接将本项目链接发送给Agent，命令其直接安装本skill。

## 十一个技能分别负责什么

| 技能 | 什么时候用 | 主要输出 |
|---|---|---|
| `$short-drama` | 初始化、继续项目、跨阶段任务、看进度、Dashboard、导出 | 项目配置、路由与项目管理 |
| `$short-drama-novel-analyze` | 分析有权使用的小说或长篇材料 | 原著快评、逐章功能、剧情单元、人物与分集候选 |
| `$short-drama-develop` | 发展点子、梗概、系列结构或接入多集整稿 | 创作简报、故事引擎、分集地图；按需导演阐述 |
| `$short-drama-write` | 写、改、规范化单集剧本，续写下一集 | `剧本.md` |
| `$short-drama-assets` | 拆人物、服装、场景、道具和状态 | `视觉设定.md` |
| `$short-drama-image-prompts` | 写定妆板、场景参考、道具与状态图提示词 | `图片提示词.md` |
| `$short-drama-storyboard` | 设计镜头、时长、调度、开场构图与图片绑定 | `分镜.md` |
| `$short-drama-video-prompts` | 将分镜写成实际提交正文，按需安排音乐意图 | `视频提示词.md` |
| `$short-drama-produce` | 调用已配置服务，实际生成图片、视频、TTS 或音乐 | 媒体与任务运行记录 |
| `$short-drama-edit` | 使用已有真实素材剪辑、加字幕和声音、导出 | `剪辑单.md` 与实际成片 |
| `$short-drama-review` | 审查文档、参考图、生成素材、成片或生产观察 | 带证据的问题、结论与修订要求|

## 开始前需要说明的参数

新项目尽量一次给全；已有项目沿用已确认值，只说本次变化。未知项可以写“未定”，先完成不依赖它的文本工作。

| 参数 | 写法与作用 |
|---|---|
| 项目路径、集号、任务范围 | 明确文件归属，以及本轮只做哪些步骤 |
| 故事与改编边界 | 人物、冲突、本集结果、必须保留项和允许修改范围 |
| 制作形态 | 真人写实、二维动画、静态漫剧、三维风格等，影响人物准备和镜头表达 |
| 画幅 | 如 `9:16`、`16:9`；实际模型入口需支持 |
| 集数与单集时长 | 集数可未定；时长写秒数，并区分固定长度或约数目标 |
| 视频模型与服务档位 | 写“2.0低价模型”“2.0mini”等完整选择，避免仅写“2.0”“便宜版” |
| 生成模式 | 参考生、首帧、首尾帧、文生；缺图不会自动切换成文生 |
| 多镜一生成 | 是否允许同场相邻镜头装进一次请求；整集只用GROUP时需明确说明 |
| 语言 | 说明语言、图片／关键帧正文语言、视频正文语言、对白口语语言分别确定 |
| 媒体由谁生成 | 自行在平台生成，或委托匹配的生产适配器执行|

## 从剧本到成片的完整流程

```text
故事或原著（可选开发）
    → 单集剧本
    → 视觉设定
    → 分镜与图片提示词
    → 准备并核对参考图
    → 视频提示词与提交清单
    → 自行生成，或预览确认后由生产技能生成
    → 核对真实素材、定点返工
    → 剪辑、字幕、声音与导出
    → 按需成片审查与资料交付
```

已有剧本可直接拆资产；已有分镜可直接准备视频文本；已有视频可直接进入素材核对和剪辑。原著分析、开发、Look Development 与正式审查按需要调用。

### 1. 编写或修改单集剧本

快速开始已完成剧本时直接进入下一步。已有项目需要单独写作时：

```text
使用 $short-drama-write，为 [项目根目录] 编写 [集号]。
依据：[当前分集规划／本集梗概]；本集追求、主要阻力、当集结果和结束状态：[内容]。
沿用已确认形态、时长与语言，保留 [必须保留项]。
按真实对白、动作与停顿核对容量，保存完整剧本，不进入资产或媒体生产。
```

需要修订时，点名实际段落、问题、允许改什么与必须保留什么。采用某版后说“以当前保存的剧本为准，继续下一步”；手动编辑的文件同样有效。

### 2. 明确人物、空间与道具

```text
使用 $short-drama-assets，根据 [项目根目录] 的 [集号] 当前剧本完成视觉设定.md。
区分人物身份、服装与状态变体、场景空间、关键道具及持续变化；重点人物分别管理，普通群演按群体与衣装管理。
沿用已确认形象，比较重点人物的可辨认差异，对必要跨镜事实设置有范围的连续性锁。
只写视觉设定，不改剧情、不写图片提示词、不生成媒体。
```

身份与变体分开：换衣、湿污、伤损、开合通常不产生新身份。左右手、机位、站位和视线等镜头瞬态由分镜落实。

### 3. 设计分镜，并准备图片提示词

```text
使用 $short-drama 协调 $short-drama-storyboard 和 $short-drama-image-prompts，完成 [项目根目录] 的 [集号] 分镜.md、图片提示词.md。
先设计每镜来源、职责、景别与机位、运镜、起点、动作过程、终点、逐字声音和时长，再按模型能力安排合法生成组。
冻结关键帧只写开场瞬间；整镜视觉依据覆盖过程，开场集合不同时单列开场依据，避免提前出现后续人物或终态。
按实际连续性需要写人物、场景和道具图片提示词，复用图点名原文件、区域和用途，同步两份文档引用。
保留总长和已确认对白，普通参考路线不额外要求逐镜首帧，特定方言条件仍遵守。只写文本，不生成媒体。
```

两份文档可以交叉推进。没有图片提示词条目时分镜可先引用已有视觉事实，不为补流程编造IMG编号。普通群演不按出场人数逐人套详细定妆板。

### 4. 自行出图，检查并绑定

复制各IMG条目下“可复制提示词”的完整正文到自己的出图工具，按该条目声明上传参考。优先准备后续素材依赖的身份、造型和空间依据。

图片放进项目后发送：

```text
使用 $short-drama 协调 $short-drama-review、$short-drama-storyboard 和已有视频文本的负责技能。
逐张检查 [项目根目录] 的 [集号] 图片：[真实文件或目录]，对照当前视觉设定、分镜和图片提示词。
每张不合格图点名原文件、问题区域、影响与可复用部分，当轮给完整可复制更正提示词；只需裁切时给具体选区指令。
只把真实可读且用途匹配的图绑定为REF，替换对应PLAN并同步已有下游顺序与图号。
本轮只审图和更新文本，不生成、编辑或裁切媒体，不虚构修订后文件。
```

图片尚不进项目时，可以明确选择自行准备与挂载，先用合法PLAN继续视频文本。实际生成时仍需对应图片；计划裁切的文件不能提前登记为REF。

### 5. 写正式视频正文与上传清单

```text
使用 $short-drama-video-prompts，完成 [项目根目录] 的 [集号] 视频提示词.md。
沿用当前分镜、已确认模型／档位、模式、语言与生成组，不改剧情、镜头边界或时长。
已有图使用REF；我会自行准备并挂载的已定图片可用合法PLAN继续，未定的必要素材如实列缺口。
新稿归组MOTION保留成员审查记录；每个GROUP和未归组独立MOTION各有唯一完整、自包含、可复制的正式正文。
列清去重上传顺序、素材职责、生效镜头与阶段、累计时间及局部到整组编号映射。
逐字保留对白，核对发声窗口、接触承重释放、持物、左右、组间切出与接入；只写文本，不提交生成。
```

正文必须能独立使用，不能靠“参见分镜／同上一组”代替内容。除非已明确开启，不生成非画内字幕与对白文字叠加；剧本允许的画内文字另按原句、承载面与出现阶段处理。

### 6. 生成视频并核对真实结果

自行生成时，对每个实际提交单位执行：

1. 核对模型与服务档位、模式、总秒数、画幅、分辨率。
2. 按上传表挂真实素材，并核对每张图的职责及生效阶段。
3. 完整复制GROUP正文；独立镜头才复制独立MOTION正文，成员不重复提交。
4. 保存实际结果，记录它对应的GROUP／MOTION与版本；回项目后用真实文件继续。

希望套件代生成时，使用后文“实际生产”，当前执行能力有单独边界。

```text
使用 $short-drama-review，检查 [项目根目录] 的 [集号] 实际视频：[真实文件与生成单位对应关系]。
对照当前来源，核对身份、造型、人数、空间、动作、持物、切镜、逐字对白、口型、声音和组间接点。
给真实时间位置与影响，区分可用、剪辑可修、须重出和未验证，保存报告。本轮只审查，不修改或重投。
```

需要返工时，由对应来源技能先修订，再生成受影响单位；保留合格素材和旧版本。一次失败只支持当前输入与配置下的观察，不自动形成所有模型的通用规则。

### 7. 使用真实素材剪辑

```text
使用 $short-drama-edit，将 [项目根目录] 的 [集号] 剪成成片。
视频及对应关系：[真实文件]；配音、音效、环境声与音乐：[真实文件或无]。
交付要求：[目标／固定时长、画幅、帧率、分辨率、字幕与声音要求]。
先完整查看素材、定位发声和可用区间，再写剪辑单、选择入出点，字幕逐字取当前剧本。
GROUP视频按实际成员内容对应MOTION；同文件可用不同区间，不虚构已拆片段。
执行必要后期并渲染到制作成果/成片/，报告实测规格与缺口；素材不足时只交片段，不生成新素材。
```

合格原声可直接保留。需要补TTS时从剧本取原句、沿用已选声音；需要配乐时由视频提示词技能写时间线音乐章节，再自行生成或使用生产技能。

内置渲染可处理其支持的裁切拼接、字幕、音效、配音、环境声与响度；`声音`说明行本身不驱动任意混音。额外转场、原声替换、规格统一等需实际工具处理并记录，不能只写交付要求就声称完成。

### 8. 检查成片、导出资料

```text
使用 $short-drama-review，检查 [项目根目录] 的 [集号] 成片：[真实路径]。
对照当前剧本、分镜和剪辑单，检查故事完整性、信息揭示、连续性、声音、字幕、实际时长和交付规格。
问题给可定位时间、证据、影响与优先级，结论限定已观察范围。本轮只审查，不修改文件。
```

处理完需要交付的内容后：

```text
使用 $short-drama，将 [项目根目录] 中 [集号或集数范围] 的当前创作文档、剪辑单和制作成果导出到项目外目录 [交付目录]。
排除原始输入、凭据与隐藏运行记录，核对实际清单并报告缺项；这是当前状态快照，不新增审批结论，不重新生成或渲染。
```

只交文字时明确“不带媒体”。普通快照导出不等于带审批证据的正式交付包。

## 模型档位、镜头与生成时长

下表是当前技能采用的配置约定，部分渠道能力来自创作者提供的服务声明。**它不等于供应商全部入口的实时能力或账号可用性承诺。**

| 明确选择    | 单次实际生成时长               | 其他重点                                                     |
| ----------- | ------------------------------ | ------------------------------------------------------------ |
| 2.0低价模型 | 只能5、10、15秒                | 720P；支持已声明的16:9、9:16、4:3、3:4、1:1、21:9；未声明视频／音频参考与同轨声音能力 |
| 2.0mini     | 未确认的时长与精度在提交前补齐 | 支持文生、首帧、首尾帧、参考生；参考生最多9图／3视频／3音频，分辨率等未知项不继承普通2.0 |
| 2.0标准     | 同上，不套低价离散锁           | 当前已声明输入能力与Mini相同，分别记录档位，不推测速度或画质差别 |
| 2.5高级     | 普通固定时长生成4～30整数秒    | 使用2.5方言；编辑、延长按对应任务契约；严格首帧／首尾帧需核对具体入口并接受相应能力 |
| Wan 3.0     | 2～30整数秒                    | 最多9图／5视频／5音频；中文自然指令；分辨率沿用同一服务已接受值 |
| MiniMax H3  | 本地方言4～15秒                | 视频正文推荐英文；具体模式组合与执行端匹配，多镜容器按其逐切图条件准备 |

Wan的视频与音频参考每段1～15秒，各类合计不超过15秒；有视频输入时，输入视频时长加本次输出不超过30秒。其他模型继续遵守其自身更严格规则，不能仅用段数判断就绪。
