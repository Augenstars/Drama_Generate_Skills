# 短剧资产图片提示词

所有模型和服务档位每次实际生成最多9张参考图片；原生或模式更低上限取小，视频/音频规则不变，资产库总量不限。详见[统一图片上限](../short-drama/references/model-service-presets.md#全模型统一参考图片上限)。超限不丢必要参考、不改剧情或时长、不静默换路线。

把视觉事实写成可复用、可修改、可直接复制的角色板、场景板、道具板或状态图提示词，统一保存到
`剧集/<EP>/图片提示词.md`。每项用 `IMG-...` 标题，正文放在 `### 可复制提示词` 引用块。
`IMG-...` 是提示词条目的稳定 ID；实际图片须由创作者提供，或来自经确认的生产结果。

每项使用 `## IMG-... · 中文名`，写一行不加粗的 `- 参考：`。无外部参考时写 `- 参考：无外部参考`；
有真实图片时使用 `REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）`。
多张用 `；` 连接，顺序从 1 连续编号；正文标题固定为 `### 可复制提示词`，每个非空正文行以 `>` 开头。
`REF-...` 指向当前项目中的真实图片；下游分镜的 `PLAN-...` 挂图计划不能证明本条图片提示词已有参考输入。

## Quick Start

```text
用 $short-drama-image-prompts 为 EP001 已确定的人物、地点和道具写可直接复制的图片提示词
```

## 入口

先确定本轮阶段、已选服务/模式与实际交付范围，按[定向读取](../short-drama/references/task-reading.md)定位对应段落；未变且已完整读取的资料复用，截断只补缺段，不默认遍历全部参考。固定引用和预算可用[派生工具](../short-drama/references/derived-data.md)从当前来源计算，不另建手工创作真相。

有当前视觉设定即可直接开始；剧本只在提示词需要确认剧情状态时读取。Look Development 是可选分支。
先确认用途：身份板、造型/状态变体、地点板、道具板、组合 production sheet 或比较风格帧。
分镜需要生产尾帧时，可把已接受的「收尾关键帧提示词」落实为独立 `IMG-...` 状态图条目：
说明来源 SHOT 与终点，沿用视觉事实和参考范围，不重新设计动作。实际生成以该 IMG 条目为来源。

创作者可读说明跟随项目语言；可复制正文跟随 `short-drama.json#/format/prompt_language`。没有
`short-drama.json` 时正文默认
使用 `en`，并在同一任务中保持一致；不能从创作者说明语言推断提示词语言。

## 明确人物传记的形象前置验证

仅用户明确要求人物传记／名人传记时，按[共享规则](../short-drama/references/biography-actor-preflight.md)区分真实叙事身份与原创演员形象。新进入本分支、尚未验证选定的重点人物先给单人候选图提示词；未限定只写图片时，同请求由 video-prompts 配对给片外短片正文，让创作者实际生成和选择，不先扩完整多造型板。

这是详细定妆默认的前置条件，不取代其规格：完成共享规则定义的验证选定后恢复本技能原有正／自身侧／背全身、面部和必要衣饰细节；功能人物、群演和未声明传记的项目不变。真实照片只按声明范围作资料；候选、PLAN、可读REF与已通过结果不能互相冒充。用户只要本轮图片候选时尊重范围，不自动生产或声称视频已测。

## 服务档位覆盖

用户点名预设表中的模型选项或项目已有accepted的`video_service_preset`时，先读[模型服务预设](../short-drama/references/model-service-presets.md)的素材与图片条款。
按实际生成组的参考预算准备必要素材：所有模型和服务每次实际生成最多9张参考图片；原生或模式更低上限继续遵守；不是资产库总量配额。
优先复用单幅/局部，未实际裁切不登记裁切REF；720P约束视频输出，不强迫参考图降为720P。
视频服务档位不自动指定图片生成模型，也不改变人物准备深度、群演人数或参考生路线。

## 工作流

1. 先读取视觉设定中的个人或群体连续性需求，判断是否确实需要新增图片，再确定详细定妆板、单幅、局部、群体参考或复用已有素材；不按出场人数逐人套用定妆模板。
2. 只读所需资产事实、视觉方向、负面约束和已提供参考图。
3. 编写重点人物提示词前，比较同批角色的身份锚点，确认其具有可读差异。视觉设定尚未提供必要区别时，向资产阶段提出具体补充建议，不在图片提示词中另造已确认身份。
4. 按“主体与身份锚点 → 当前变体 → 构图/视角 → 光色/材质 → 背景边界 → 禁止项”写正文。
5. 每张参考只控制已声明的范围，并在 `REF-...` 槽位里写出封闭词表中的 `用途`；具体范围见[通用配方](references/common-recipe.md)。
6. 检查身份与变体、文字政策、视角和光线是否冲突。用户本轮要求审阅实际图片时，对不合格图逐张按[图像审阅反馈](../short-drama-review/references/rubric-assets-prompts.md#图像审阅的逐图反馈与更正提示词)写明原文件、问题和可复制更正提示词，不只给修改方向；不因此擅自开始媒体生成或扩成全库审图。
7. 用户要全部资产就完成全部，资产组只是内部批次。仅明确传记分支中尚待创作者实测／选择的人物，先完成候选及已授权配对测试文本并列清受影响的未决项；其他不依赖该面孔的资产继续完成，不把候选交付冒称全库已定妆。

## 提示词要求

- 开头先写对象和用途，不用风格词淹没身份。
- 只包含当前图能同时满足的要求；多视图/状态对照写清版面关系。
- 保留稳定识别锚点，变体只改允许变化的部分。
- 同一人物各视图保持同脸，不同重点人物采用各自的身份锚点。用于版式、服装或风格的他人参考图，不承担当前人物身份。
- 被《视觉设定.md》连续性锁点名的条目，锁面原样出现在可复制正文里，让这张参考图本身就把跨镜事实定住。
- 避免无验证作用的质量词堆砌。
- 可见文字、logo、水印、界面和字幕明确允许或禁止。
- 正文可直接复制，不含占位符、流程说明、文件路径或 QA 结论。
- 人物图片按实际身份辨认与连续性需求确定准备深度。主要角色和需要持续辨认身份的重点配角默认采用详细定妆板；短暂功能人物按需使用单幅或局部；普通群演默认复用群体衣装与现有可用素材，不逐人生成详细定妆板。
- “人物定妆”“分别制作人物板”等一般要求，不自动扩展为给全部背景群演逐人建板。创作者逐名指定或明确要求群演也详细定妆时，按其要求执行。
- 既有图片可通过裁切满足用途时不新增图片。复用项必须说明具体原文件名、项目相对路径、所选分格／区域及用途，不能只写“复用旧图”；无可核实原文件则保留计划或缺口。依[复用图片定位](../short-drama/references/reference-roles.md#复用图片必须可定位)写清直接复用、裁切或修订，未裁片不登记REF。普通群演缺少独立人像图，不作为必须补图的理由。
- 场景资产默认采用“空间一致性参考组”：同一地点维护场景基准图、俯视空间结构图和多视角参考板。多视角板默认采用3×3九宫格，包含正向、侧向、反向三个主要观察方向；创作者明确要求三视图时改为三个分区。各视图只改变合法机位与观察方向，不重新设计空间。具体规则见 [场景空间一致性参考组](references/location-plate.md#7-场景空间一致性参考组)。
- 场景图只建立地理、固定设施和光色依据，不代替分镜中的构图与起始状态。后续制作首帧时选取匹配视角的单格或局部参考，不默认把整张九宫格作为首帧构图。
- 本技能只编写提示词与参考使用说明，不生成图片；新增提示词不代表相应图片已存在。不得承诺仅凭多视角提示词就能完全消除空间漂移。
  
  ### 用于参考生视频的素材交付

当下游采用参考生视频时，图片资产直接服务于视频模型，不要求先合成为
每镜起始帧。

- 保留人物定妆板、场景空间参考组和必要的道具状态板，作为设计与核对依据。
- 同时说明实际挂图时应使用的单幅或局部：人物优先使用身份清晰且造型正确的
  单人图；场景优先使用对应机位的单格；道具优先使用本镜需要的单一状态。
- 不要求所有资产都增加新图片。现有图片可以通过裁切满足用途时，说明裁切范围；
  仅在缺少必要细节或视角时追加图片提示词。
- 角色多视图不代表多个角色，道具状态对照不代表同时出现多个道具；
  将这一点写入下游使用说明。
- 左右手、缺角、标识和非对称结构按对象自身方位描述，不以画面左右代替。
- 场景俯视图用于空间关系，场景单幅图用于外观与视角；二者均不决定本镜人物
  站位、持物和动作状态。
- 本阶段只准备图片提示词及素材使用说明。逐镜参考绑定由分镜阶段维护，
  视频中的动作和声音由视频提示词阶段维护。

## 完成与投产

每个点名对象都有明确用途、可复制正文、参考边界和禁止项，且相互不矛盾，即完成。本次请求同时
修改图片提示词与分镜时，当轮刷新受影响镜头的「图片提示词项」，不另建对账产物。实际生成必须
转 `$short-drama-produce`，展示精确任务并取得显式确认；本技能不调用外部服务。
写完本阶段文档后，可转 `$short-drama` 做局部机械核对（只核对已有文档）；五份齐备后再做完整核对。内容质量仍由创作者审查。
