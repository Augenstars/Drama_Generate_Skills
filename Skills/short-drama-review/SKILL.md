# 短剧审查

所有模型和服务档位每次实际生成最多9张参考图片；原生或模式更低上限取小，视频/音频规则不变，资产库总量不限。详见[统一图片上限](../short-drama/references/model-service-presets.md#全模型统一参考图片上限)。超限不丢必要参考、不改剧情或时长、不静默换路线。

优先由未参与当前版本创作的 reviewer 执行；条件不允许时可以自检并如实说明。本技能定位问题、影响和
必须达到的修订结果，将来源文件的实际修改交回负责技能；审查与修改分开执行。

用户委托审阅实际图片时，每张不合格图都要明确原文件名、路径／链接、问题区域、影响与可直接复制的更正提示词，按[逐图反馈规则](references/rubric-assets-prompts.md#图像审阅的逐图反馈与更正提示词)执行。该正文属于审查结果中的修订建议，当轮直接给出，不以“请图片技能处理”推迟；不自动覆写《图片提示词.md》等来源文件，也不生成或裁切图片。复用说明同时遵循[具体原图定位](../short-drama/references/reference-roles.md#复用图片必须可定位)。

## Quick Start

直接读取用户点名的当前文件。单集审查需要落盘时写 `审查/EP001-审查.md`；独立文件审查使用
`审查/<主题>-审查.md`。用户只要口头结论时直接回复，不为“完整”创建审查文件。

审查 Markdown 建议结构：

```markdown
# EP001 审查

- 范围：剧本、分镜、视频提示词
- 结论：REVISE
- 复核方式：独立 reviewer / 自检

## Blocker · REV-001 · 画面文字未被镜头承载
- 位置：剧本.md / EP001-SC002；分镜.md / SHOT-EP001-004
- 证据：……
- 影响：……
- 修订结果：由 short-drama-storyboard 补入准确文字及可读条件。
- 规则：SHT-01 · structural_invariant
```

引用只使用文件名、标题 ID、行号或短引文；不建立 sources 声明、哈希、record ID 或第二套状态。

## 已选服务档位

本轮点名预设表中的模型选项或项目已接受`video_service_preset`时，先读[模型服务预设](../short-drama/references/model-service-presets.md)，只按命中档位审查。
低价版核对GROUP的5/10/15秒、固定整集总长、720P、画幅与全模型统一9图上限；不要把组内4秒SHOT误报违规。
Mini/标准各核对参考生9图/3视频/3音频；未知能力不臆测，2.5高级沿用原设定。
本地机械校验不替代真实输入、图号映射、表演容量与媒体结果的检查，也不授权修改来源文件。

## 明确人物传记的形象验证证据

仅在用户明确选择人物传记／名人传记，且本轮审查涉及人物视觉或测试结果时，按[共享规则](../short-drama/references/biography-actor-preflight.md)核对叙事身份与原创演员是否分开、候选和已选是否混淆、平台结果／制作质量／创作者选择是否各有证据。待测候选不等于已通过，不把用户仅选图解释为视频生成成功。

本轮范围含传记开发／剧本／全片叙事时，同时按[类型与事实边界](../short-drama/references/biography-context.md)区分关键史实、戏剧重现和待核材料；仅审视觉不自动扩成全剧调查。创作方案被接受不证明生平事实已核实。

片外测试不能混入正式镜头与总长；未声明传记的原创项目、无名功能人物及普通群演不因没有该测试而被判缺陷。已有证据按版本和适用范围沿用；只审获授权范围，不因此启动生产或改写来源文件。

## 戏剧推进与组间衔接审查

审查剧本时按[戏剧推进](references/rubric-story-script.md#戏剧推进与短剧吸引力)找具体目标、阻力、回应与后果，区分剧情空转与有内容的停顿，不把倍速、镜头数、争吵或反转配额当作吸引力。
审查分镜/视频提示词时按[相邻GROUP接点](references/rubric-visual-motion.md#相邻group的接点与过渡)逐对核对切出、接入、揭示、声音及预算；有职责的空镜可保留，硬切不是自动缺陷。
报告位置、证据、影响、需要达到的修订结果及优先级，并指明owner；不能泛泛建议“更激烈”或“加个转场”。不承诺规则修改已提升留存率或实际成片接得平滑。

## 工作流

### 1. 确定范围

写清当前要审哪些文件、章节、镜头或提示词，以及创作者已经明确的限制。目标在审查中发生变化时，
重新读取再下结论。

### 2. 先查可证明事实

- 五文档的可见 ID、引用和时长是否一致；
- 剧本对白、动作、声音、画面文字是否都有画面/声音承载；
- 人物、地点、道具状态和镜头起止是否连续；
- 提示词是否从准确起点到准确终点；
- 目标模型画音同轨时，声音内容、时序和发声边界是否与来源一致；无对白镜是否交代底声或静默
  （`VID-22`、`VID-23`，见 [视觉运动审查表](references/rubric-visual-motion.md)）；
- 私有输入、凭据、绝对路径或内部流程文字是否泄漏。

缺少必要输入时只停止依赖它的判断，其他问题可以继续汇总。

### 3. 带证据审内容

每个 finding 包含位置、必要短引文或冲突事实、观众/制作影响、必须达到的修订结果、负责技能、严重
程度、规则等级和 `open` / `closed` 状态。“AI 味”“不够电影感”或无证据分数不能替代这些内容。

### 4. 跨文档综合

```text
剧本事实 -> 视觉设定 -> 镜头职责与边界 -> 冻结关键帧 -> 视频运动 -> 下一状态
```

优先守住原意、知情时机与连续性，不奖励脱离来源的华丽提示词。

### 5. 结论与分派

- `APPROVE`：没有阻断问题；
- `APPROVE_WITH_NOTES`：只有不阻断的改进；
- `REVISE`：存在阻断交付的结构缺陷、经证据确认的内容缺陷或已接受限制冲突；
- `PROVISIONAL`：关键输入不足，暂时无法完成判断。

按负责技能分组修订要求；不合格图片的更正提示词已在本轮审查结果内交付，不能只列“重做”后就结束。本轮完成后交还控制权；来源文件实际修改、图像处理和复审按用户授权范围执行，不把修订建议视为这些动作已经完成。

## 严重程度

- `blocker`：不安全、不可交付或会让流程走错；
- `major`：明显破坏剧情理解、连续性或制作结果；
- `minor`：有具体影响但不阻断；
- `note`：创作选择或可选润色。

## 边界

- 不提交图片、视频、TTS 或音乐任务，不配置 adapter，不把 Dashboard 操作当生产授权。
- 无法读取媒体时明确限制，不从文字或 adapter 状态推断脸部一致、表演、口型、混音或市场表现。
- 生产观察必须绑定准确输入、提示词、参考、配置和结果版本；不能泛化成通用规则。
- 审查文件只保留修订所需的最小证据，不复制完整私有输入。
