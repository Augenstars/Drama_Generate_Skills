# 短剧分镜与冻结关键帧

所有模型和服务档位每次实际生成最多9张参考图片；原生或模式更低上限取小，视频/音频规则不变，资产库总量不限。详见[统一图片上限](../short-drama/references/model-service-presets.md#全模型统一参考图片上限)。超限不丢必要参考、不改剧情或时长、不静默换路线。

把剧本和视觉事实转成有镜头职责、空间连续性和可冻结起点的 `剧集/<EP>/分镜.md`。
每镜使用二级标题 `## SHOT-...`，同镜下用 `### 冻结关键帧提示词` 写起始帧正文；
需要时另加 `### 收尾关键帧提示词` 写终点正文。

## Quick Start

```text
用 $short-drama-storyboard 完成 EP001 的正式分镜和每镜冻结关键帧
```

## 入口

先确定本轮阶段、已选服务/模式与实际交付范围，按[定向读取](../short-drama/references/task-reading.md)定位对应段落；未变且已完整读取的资料复用，截断只补缺段，不默认遍历全部参考。固定引用和预算可用[派生工具](../short-drama/references/derived-data.md)从当前来源计算，不另建手工创作真相。

当前剧本加必要视觉事实即可直接进入。资产图片提示词与分镜是兄弟分支，不互相等待。只有关键场次
真的存在多个成立导演方案时，才在上下文比较覆盖方案；普通场次直接设计。

创作者可读说明跟随项目语言；冻结关键帧的可复制正文跟随
`short-drama.json#/format/prompt_language`。没有 `short-drama.json` 时正文默认使用 `en`。
分配镜头时长前读取
`short-drama.json#/creator_authority/production_profile/choices/native_duration_seconds`。已声明目标模型但
没有原生时长时仍可写叙事分镜草稿，并明确接口时长合法性未验证；执行就绪前再补该能力。目标模型也未声明时照常设计，不猜供应商限制。
同时读取 `short-drama.json#/creator_authority/rhythm_profile`：`status` 为 `accepted` 时，镜长按
[镜长从哪来](references/shot-craft.md#镜长从哪来-sht-28) 由声音事件与 `target_avg_shot_seconds` 推出，
全集近景类镜头占比不低于 `close_shot_share_min`；档案缺失或未接受时不核对这些数值。

冻结关键帧成稿后，再按画面中的可见内容填写视觉依据、图片提示词项和输入参考图，
避免只按镜头意图列资产而漏掉实际入画的人物或物件。
参考生视频的视觉依据覆盖整镜；若人物/造型只在过程中入画，另写`- 开场视觉依据：...`列开场实际可见子集，开场为空可写`无`。语法与视觉依据相同。未写时为兼容旧稿默认两者相同；有阶段差异的新稿必须明确，不把后续人物写进冻结起点。

人物参考需求按个人身份辨认、造型或群体连续性分别判断。普通群演可引用已有的群体或造型条目，不因本镜存在某个人体或新增站位编号，就要求独立人像图或详细定妆板。

前列、中列、队尾和临时职责由调度落实，不自动生成新角色。为解决同时占位或持物冲突，先检查原有人员是否能按真实时序移动、松手或归位；不以增加未明确存在的额外群演作为默认解决办法，也不擅自合并剧情确认的不同人物。

用户没有手工点名参考图，不等于选择文生视频。冻结关键帧后先根据本镜可见人物、地点、关键道具与
起始构图判断一致性需求，再检查项目中已有的真实图片。只有当前可读、内容与用途可核对的图片才能自动绑定；
文件名像某个角色但内容未核对时，仍视为未准备好。

项目里没有所需图片时，一次向创作者说明三条可选路径：把手上已有的图片放进项目再绑成 `REF-...`；在自己的工具里出图、本轮先用
`PLAN-...` 写出挂图计划；或者明确改走文生视频。用本套件的生产技能出图只是第一条路的一种做法，
需要项目外的 adapter 与凭据，不是唯一入口。

开始分镜前读 `剧集/<EP>/剧本.md` 的当前内容。创作者说「剧本已确认采用」指的是那个文件，
不是对话里更早的草稿；两者不一致时以文件为准，并把差异说出来。

## 明确人物传记的候选边界

仅用户明确选择人物传记／名人传记时，按[原创演员前置验证](../short-drama/references/biography-actor-preflight.md)读取人物的候选／选定状态。候选阶段仍可设计剧情、调度和分镜草稿，但不能把未选面孔写成既定身份或伪造参考文件。自行挂图的PLAN仍须定位本项目实际存在的IMG／SHOT条目；片外测试单不冒用这些ID。

图片候选及验证短片不计入正式SC／SHOT／GROUP、成片时长或生产清单。选定后沿同一演员身份投影既有视觉事实，原有图数、镜头、连续性和参考生规则不变；不对原创项目、功能人物或群演新增测试门槛。

## 服务档位覆盖

本轮明确点名预设表中的模型选项，或项目已接受`video_service_preset`时，先读[模型服务预设](../short-drama/references/model-service-presets.md)。
低价版每个实际生成GROUP只允许5/10/15秒，组内SHOT按剧情定时；独立生成的单镜也受GROUP档位约束。
先核算固定集长，再分组，不能逐组取整导致超时。Mini/标准/2.5不继承低价限制。
组内累计区间、切换和整组去重参考预算在本阶段落实；不增加每镜真实首帧要求。

## 工作流

1. 读取已接受的目标模型原生时长区间，再确认每个场景动作、对白、声音、画面文字和转折由哪些镜头承载。
2. 确定观众何时知道什么、对齐谁、空间如何揭示、转折落在哪个可见动作。
   剧本或 Brief 用“前半段 / 后半段 / 前三分之一 / 最后 N 秒”等相对时间限定首次出现、释放或禁止时，
   先用已接受集长换成明确时间边界再分镜；例如 60 秒作品的“后半段首次出现”不得早于 30 秒。
3. 每镜写清唯一职责、来源、时长、景别/机位、运镜、起点、唯一主要动作、终点和声音；用
   `起点 → 唯一动作 → 终点` 直接说明人物、双手与持物怎样完成本镜状态转换。三条依据留到第 6 步。
   数一下这一镜要观众看清的事，按镜长判断每件有没有足够的时间被看清；放不下时先删、合并或拆镜，见 [短镜头的动作量](references/shot-craft.md#短镜头的动作量-sht-03)：视频模型不会删掉多出来的动作，而是把它们压到看不清。
   「运镜」按本镜目的逐镜选，写行为和理由，固定也写理由，见 [运镜逐镜选](references/shot-craft.md#运镜逐镜选-sht-04)。
   有对白、VO 或 OS 时，先按原文和人物说话方式估算完整发声时间，再安排不能重叠的动作、停顿与
   末尾反应；把估时依据简写在本镜「声音」里。具体做法见 [对白估时](references/shot-craft.md#对白估时)。
   对白场先按 [对白覆盖默认](references/shot-craft.md#对白场怎么切-sht-29) 放切点；镜长不按剧本字数折算。
4. 一场戏拍成多镜时，先在《分镜.md》开头写这场的「场景站位」：固定锚点、各人相对锚点与彼此的位置、轴线与 working side、哪一镜改变站位。再逐镜锁定朝向、位置、视线、持物、出入口和必要状态，与「场景站位」一致；起点、终点里的位置写锚点和人物关系，视线写看向谁或什么；冻结关键帧再把它翻成本镜机位下的前后景、朝向、中间隔着什么和画面左右，见 [站位先写锚点和关系](references/blocking-playbooks.md#站位先写锚点和关系)。上游已有会限制动作空间的持续关系时，把关系投影进本镜起点与终点。
5. 冻结关键帧只投影镜头起点；删除终点才出现的文字、动作、姿态或道具状态。
   镜头的职责落在收尾那一下时，另写 `### 收尾关键帧提示词` 投影**终点**——同一格画面的
   另一端，规则完全对称：删除起点才有、终点已经不在的东西。它是可选的，写法与取舍见
   [首尾成对](references/shot-craft.md#首尾成对)。
6. 关键帧成稿后，按当前生产用途确定参考素材范围：
   首帧图片所需素材覆盖开场画面；
   参考生视频所需素材覆盖本镜起点、动作过程与终点。
   据此填写视觉依据、图片提示词项和输入参考图。
   后续才入画的素材必须注明生效阶段，不改变冻结关键帧的开场内容。
   
   - **视觉依据**：清单里每一项写成《视觉设定.md》的条目引用，这是必写字段；
   - **图片提示词项**：清单里已有合适 `IMG-...` 条目的写上，没有的留「无」；
   - **输入参考图**：按清单在用户提供的输入、`剧集/<EP>/制作成果/` 和文档已指向的其他可见媒体中查找匹配图片；
     命中就写入 `REF-...`。一张都没命中时写「无（待补参考图：<本镜所选模式实际需要但缺失的参考素材>）」；
     只命中一部分时，在已有 `REF-...` 后追加「；待补参考图：<仍缺的图片>」，缺口之间只用 `、` 分隔。
     创作者说图片由他自己在别处准备时，把这份清单写成 `PLAN-...` 槽位，本镜即告就绪；
     只有创作者明确表示不用图时，才写「无（创作者已明确选择文生视频）」。

三条依据不得相互矛盾。冻结关键帧中可见的必要条目必须被覆盖；
参考生视频还应覆盖镜内后续入画的必要条目，并注明其适用阶段。
   目标模型或服务档位有参考上限时，先按实际提交单位去重、复用并去掉冗余或非必要参考；必要身份／状态／空间依据不按排名删除。仍超限时按已授权范围调整打包，不能保持已确认镜头与分组时提出具体上游修订，不静默删必要参考或换路线。文字事实按开场、过程和终点各自生效，不把后续素材统一塞进冻结起点。
7. 整集请求完成整集，末端一次报告覆盖、节奏和真实未决选择。

## 一次生成内的多镜剪辑

用户要求“一段内切镜、多镜一生成”时，把它作为明确的交付选择，不再为同一选择重复询问；有项目时按 `$short-drama` 既有决策流程记录 `multi_shot_containers: true`。仅修改 skill 不代表修改已有项目的已接受交付选择。

新增分镜明确生成组后，每镜写`- 生成组：GROUP-...，组内0—4s`，独立镜写`无`；开头分组表由这些字段归并，保持成员、顺序与累计时间同源。旧稿未声明逐镜计划时不强制补字段。视频GROUP必须继承已有明确计划，改组先同步分镜。

新分镜可优先按同场连续动作、正反打或反应镜组织生成组，但保留每个 SHOT 的独立职责、时长、起终边界和冻结关键帧文字。在《分镜.md》首个 SHOT 前列出生成组、顺序相邻的成员、组内起止秒数、总时长与切换方式。视频阶段将同一成员关系落实为 GROUP；不能把三镜写成一个含暗中切镜的 SHOT。

同一地点改变机位、景别或正反打不自动拆组。检查轴线、目光、持物以及整组参考覆盖；不同视角素材可以分别生效，不等于资产身份变化。跨场次、时间跳跃或尚未解决的素材矛盾先拆组，明确当前校验器不接受跨场次 GROUP。需要跨场蒙太奇时另作有边界的设计与校验支持，不能为了过检查伪造同一场次。

单独提交镜头受接口原生时长及已选服务档位约束；组内子镜受叙事节奏约束，接口时长约束作用于整组。组内可以有半秒切点，总时长须满足目标接口要求。冻结关键帧文字仍逐镜保留；参考/文生模式不因多镜打包新增每镜真实首帧要求。旧项目只合组、不擅改已接受时长和剧情；合组超限时拆组。

正文写明切至反打/切至近景/匹配剪辑等，不用“无缝”掩盖必要切换。时间戳是计划切点，不能保证生成精确落点；精确计时剧情必须在生成后实测，必要时另作剪辑。

## 相邻镜头与生成组的接点设计

整集分镜读[接点设计](references/shot-craft.md#相邻镜头与生成组的接点设计)，逐对连看相邻GROUP。先判断同场延续、换景、跳时、穿越或有意反差，再选择动作/视线接剪、空镜、声画呼应、声音桥或特效；硬切本身不是缺陷，不强制每组加过渡。
普通接点一句写明切出与接入的依据；关键转场在生成组说明或相邻镜头中写清叙事职责、揭示点、前组切出阶段、后组开场状态、方向/持物、声音、生成与后期责任，以及已有预算如何分配。
空镜按空间、时间、情绪、后果或注意转移的职责判断，无人物、无对白或静态不等于无用。若新增一次切换，单列SHOT并同步成员；不能藏切、跨场硬合组或把环境段加在总长之外。
穿越沿既有剧情明确触发、变化、到达和人物反应，不靠“无缝转场”四字代替可见过程；终点是切出瞬间，不默认停演等下一组。
低价版只锁GROUP的5/10/15秒，短空镜可作为组内镜头；其他模型继续按各自能力。参考生路线不新增每镜真实首帧要求。

## 镜头要求

- 每镜有唯一职责、明确来源、可见起止状态和合理时长。「来源」以《剧本.md》里真实存在的场景 ID 开头，
  ID 之后可以跟必要短引文，跨场次的镜头用 `、` 连写多条；`creator_markdown_check.py` 会核对每个 ID 都解析得到。
- 「来源」短引文应对应本镜承担的动作或声音。正文提到画外人物时，可在视觉依据写
  `；画外：<类别>「<名称>」`；这只声明其不在画面，不能代替必要动作的落实。
  需要看见的动作应另有镜头承载，或说明为何省略。

- 剧本里的每个场景都要有镜头承载。确实决定不拍某一场时，在《分镜.md》正文开头写一行
  `- 未拍场次：<场景 ID>（理由：……）`，多项用 `；` 连接。省略理由必须留在成稿文档中，供下游区分有意省略与遗漏（SHT-01）。
- 已声明原生时长时，每镜照常有自己的唯一职责、起止边界和冻结关键帧，镜长先按叙事需要定。短于最短秒数
  的镜头，向创作者提议把同场相邻的几镜装进一个多镜容器；创作者同意后由 `$short-drama` 在生产档案里写入 `multi_shot_containers: true`；目标方言要求时，容器的每一切
  都要有已接受的关键帧图片，能否装、怎么装由 `$short-drama-video-prompts` 的方言决定。创作者没有声明
  多镜容器、或方言不支持时，镜头落在最短秒数内，动作完成后保持终点。长于上限的动作按可见状态闭合点拆镜，
  拆出的每镜仍各有唯一职责与可信交界。目标模型只收整数秒（如 Seedance 2.0 手动时长）时，单独生成的镜头写
  整数秒；准备装进同一个多镜容器的短镜可以写半秒，但同一容器的成员加起来必须是整数秒，在分镜阶段就排好，
  不留到视频提示词阶段分组时才发现凑不齐。
- 「唯一动作」写从本镜起点到终点的那条可见状态链；涉及交接、换手、放置或取回时，把接触者、
  接触方式和物件落点写在同一链里，不能让合法终点之间靠镜外瞬移衔接。
- 切镜必须带来信息、权力、情绪、空间或节奏变化；同义重复镜头删掉。
- 相对时间词约束的是事件首次可见或可听的时刻，不因前置动作已经完成就提前释放；分镜时间轴直接
  写出该边界，不把“稍后”“交接后”等叙事顺序当成数值时间的替代。
- 同一动作不跨镜重复发生，峰值处声明过的[冲击重复](references/shot-craft.md#动作落实表)除外；终点应能成为下一镜可信起点。
- 关键信息的可读性优先于装饰性运镜，竖屏构图优先保证主体和反应可见。
- 复杂群戏先在「场景站位」里锁空间锚点、人物位置和轴线，再决定景别变化。
- 起终边界除了逐人姿态，还要写清本镜依赖的身体—物件—空间关系。关系在镜内不变时两端都保留；确需改变时，过程与终点必须有剧本依据。
- 冻结关键帧只写该瞬间能看见的内容；文字、手指、反射和遮挡要可生成。
- 近景类关键帧挂着地点板生成时，图片常被拉宽成中远景；正文写具体取景（画面切在哪、脸在画面哪里、机位距离），出图仍偏宽就这一镜不挂地点板，把背景写进正文。
- 一集关键帧沿用同一画风；同一场景的光色按已确认光态及其变化范围写，不能抹掉镜内开灯、熄灯或天气变化。文本分镜不新增出图前提。已有合格定调图时按需复用并计入参考预算；用户明确要Look Development或图片生产时才另行准备定调图，并遵守相应生产确认，不要求参考生视频先逐镜出首帧。
- 《视觉设定.md》的连续性锁在生效镜头上原样写进冻结关键帧正文；锁面不因“参考图会交代”而省略。
- 检查发现遗漏就直接修正文档，不生成覆盖表来证明自己检查过。镜头块里的「视觉依据」是本镜的依据字段，不属于额外覆盖表。

## 视觉依据与图片

- `IMG-...` 是《图片提示词.md》里的**提示词条目 ID**，不代表图片已生成、已提供或可用。
- 已有《图片提示词.md》且本镜需要其中条目时，写「图片提示词项」：ID 必须匹配该文档的可见二级标题，同时写中文名称和它控制的身份、造型、地理、构图或其他边界。ID 只用于查找，不让英文 slug 承担含义。
- 没有《图片提示词.md》或没有合适条目时，写「图片提示词项：无」，再以中文指向《视觉设定.md》的人物、地点或道具项及控制范围。这是正常直接入口；不为继续分镜而编造 ID，也不补造另一个阶段。
- 「视觉依据」是每镜必写字段：冻结关键帧成稿后按实际画面反查，需要保持身份、造型或地理的可见人物、地点和道具**必须**逐项写成
  `《视觉设定.md》·<人物|造型|地点|道具>「<名称>」（控制：<范围>）`，多项用 `；` 连接，名称必须能在《视觉设定.md》里找到同名标题。
  小比例或背景人物只要需要认出身份仍在范围内，画外人声和不可识别局部不算；本镜确实没有这类条目时写「视觉依据：无」。
  群体连续性可以引用已存在的群体或造型条目，不等于成员共用同一张脸；列入视觉依据不意味着必须另有个人IMG条目或独立人像参考。
- 关键帧正文出现了某个条目的名字，但它本镜确实不在画面里（物主已离场、名字只出现在屏幕文字上、和某个词同形），
  在「视觉依据」末尾追加 `；画外：<类别>「<名称>」`。该声明只说明名称被提及，人物或物件并未入画。
- 某个条目的名字在正文里根本不可靠（`道具「手机」` 会撞上「手机店」，`人物「小雨」` 会撞上「下着小雨」），
  请视觉设定负责技能在该条目写 `画面代称：无`，机械核对就不再按名字找它；这一镜是否画到它仍由「视觉依据」如实回答。
冻结关键帧只描述镜头起点的可见内容。

参考生视频时，视觉依据、图片提示词项和输入参考图需要检查整镜的
起点、动作过程与终点，覆盖镜内入画且需要保持一致的人物、场景、
关键道具及必要状态。

对于只在镜内后续出现的素材，控制范围必须注明其生效阶段，
并明确不得改变开场状态。不得为了匹配后续参考图，
把人物、道具或终点状态提前写入冻结关键帧。

首帧与整镜需要不同素材集合时，不假定生产工具能自动筛选。
需要由套件生产首帧时，可将已接受的冻结关键帧落实为独立 IMG 条目，
配置仅适用于开场的参考绑定，并以该条目作为图片生产来源。
不得通过临时删改视频参考清单来绕过生产核对。

视频生产时，使用适用于整镜的参考素材。
 整镜始终只出现屏幕和一根手指的镜头不写「体态」。上一镜的绑定不因为“角色还在这场戏里”就顺延到下一镜。
- 关键帧正文点名的人物、地点或道具（《视觉设定.md》条目名称或它声明的「画面代称」），必须出现在本镜「视觉依据」里；
  `creator_markdown_check.py` 会机械核对这一条。它只抓**被名字点到**的那一类：正文只描述不点名
  （"a boy in a hooded jacket"）时机器不发声，画面里有谁仍然要靠这一步自己读出来，不能等报错。
- 本镜需要保持一致、但《视觉设定.md》里还没有条目的可见物件（跨镜出现的道具尤其常见），不能因为
  「写不进视觉依据」就当它不需要一致性。四镜都出现的一支笔和一件外套是同一类问题。做两件事：
  正文里逐镜用完全相同的描述把它钉住，并在本轮末尾报告里点名它、建议 `$short-drama-assets` 补条目。
  不自行新增《视觉设定.md》条目，也不把它塞进「视觉依据」冒充已有条目。
- 「输入参考图」是独立的另一条轴：创作者已提供，或经确认生产且当前可读的实际图片，用不同于 `IMG-...` 的稳定 `REF-...` 槽位引用。每个槽位同时写显式顺序、仅用 `/` 分隔的项目相对路径、中文名称、「用途」、「控制」和「不得控制」范围；没有时必须区分「待补参考图」和「创作者已明确选择文生视频」，只准备了一部分时则保留已有 `REF-...` 并追加「；待补参考图：……」。不得把提示词条目、还没生成的图或对话中的描述写成 `REF-...`——`REF-...` 的意思是「文件此刻在项目里」。
  创作者会在生成时自己挂载的图片走下面的 `PLAN-...`：它同样不声称文件存在，只是把这一镜要挂哪几张写清楚。
- 每个 `REF-...` 必须逐字遵循唯一格式：`REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）`。注意「顺序：」后的全角冒号和路径前的中点 `·`；不得用 `/` 代替字段分隔符。多图只用中文分号 `；` 连接，部分缺图则在最后一个完整槽位后接 `；待补参考图：<缺口>`，缺口之间用 `、` 分隔。写完后按此格式回读一次再交付。
- `用途` 只能取 `身份`、`造型状态`、`地理`、`构图`、`尺度`、`效果`、`起始帧`、`结束帧`、`风格` 之一；逐条能控制什么见 `$short-drama` 的《参考角色》。
  本镜的起始画面图写 `用途：起始帧`，人物图写 `用途：身份` 或 `造型状态`，场景图写 `用途：地理`，道具状态图按它决定的那一件写。
  一张图承担两件事就拆成两个槽位；一镜最多一张 `起始帧` 和一张 `结束帧`，写 `结束帧` 时必须同时有 `起始帧`。
  下游视频提示词靠 `用途` 说清「本镜送哪一张分镜起始帧、哪些人物/道具/场景图」，所以缺 `用途` 的槽位不算准备好。
- 是否需要真实起始帧图片，由本镜选择的参考方式决定，不由是否已经编写
  「冻结关键帧提示词」决定。

  - 首帧或首尾帧生视频：需要对应的起始帧图片。创作者可以自行生成后放进
    项目，绑定为 REF；也可以明确选择由自己在平台挂图，先建立 PLAN。
    需要由本套件生成时，以当前 SHOT 的冻结关键帧正文作为图片生产来源。
  - 参考生视频：可以只绑定人物、造型、场景、关键道具等参考图片。
    不强制增加用途为「起始帧」的槽位，不因缺少起始帧图片而判定未准备好。
    冻结关键帧仍然保留，用于定义开场取景、人物站位、视线、遮挡、双手和
    道具状态；下游视频提示词必须将这些事实写成开场画面要求。
  - 文生视频：仅在创作者明确选择不用图片时采用，沿用原有文生视频规则。

  若创作者额外提供开场构图参考图，可以在参考模式中使用，但必须区分：
  它是帮助模型组织开场画面的参考，不代表供应商严格执行 first_frame 约束。
- 创作者在项目外出图、图片不进项目时，用 `PLAN-...` 槽位：语法与 `REF-...` 逐字相同，只把项目相对路径
  换成 `IMG-...` 或 `SHOT-...` 条目 ID，`IMG-...` 的中文名称必须与《图片提示词.md》标题一致。
  它声明的是「这张图由创作者在生成时按这个顺序挂载」，不声称项目里有文件，因此不是「待补」，
  也不能拿来投产。真实文件进了项目就改写成 `REF-...`。两种槽位可以混用，`顺序` 统一连续编号。
- 自动绑定不是把所有图都塞进一镜。只选本镜可见、且身份、造型、地理、关键道具状态或起始构图确实需要稳定的图；逐张写清它的用途、能控制什么、不得控制什么。复用须按[具体原图定位](../short-drama/references/reference-roles.md#复用图片必须可定位)说明原文件名、路径和选区。用户本轮委托逐图审阅时，不合格图按[逐图反馈与更正提示词](../short-drama-review/references/rubric-assets-prompts.md#图像审阅的逐图反馈与更正提示词)交付，不以“交回图片负责人”省略更正正文。
- 两条轴可以独立组合：有合法的图片提示词项时，输入参考图仍可为「待补」或创作者明确选择的文生视频；创作者给了真实参考图时，图片提示词项也可为「无」。

### 参考生视频的素材绑定与旧稿迁移

用户明确选择参考生视频时，只绑定本镜需要的参考素材，不默认先生产首帧。

1. 读取当前剧本、视觉设定、分镜和已选模型方言，保留镜头 ID、时长、景别、
   机位、起点、动作、终点及冻结关键帧。选择生成模式不构成改写剧情的授权。
2. 核对素材内容后使用 REF；创作者明确将在平台自行挂图时使用 PLAN。
   PLAN 仅表示文本提示词可继续编写，不表示文件存在或可以自动投产。
3. 每张图采用现有槽位语法和用途词表。人物使用「身份」或「造型状态」；
   场景使用「地理」；道具外观与状态通常使用「造型状态」；
   专门的构图参考使用「构图」。不得自行增加「道具」等用途枚举。
4. 从旧首帧流程迁移时，移除不再计划生成和上传的 PLAN 起始帧槽位。
   保留冻结关键帧正文，不删除实际图片文件，不移除创作者仍明确需要的参考图。
5. 按最终上传清单重新连续编号，并同步受影响的下游引用。不得留下正文中的
   图号与清单顺序不一致的情况。
6. 场景多视角板优先选取对应机位的单格；俯视图只控制空间关系，不控制
   视频的观察角度。人物定妆板和道具状态板优先选用本镜需要的局部或单状态图。
   尚未取得裁切图时，写明所需区域，不虚构已存在的裁切文件。
7. 同一人物不同造型的参考图必须说明身份关系；实际出现几个身体、分别处于
   什么位置和状态，由当前分镜决定，不能按参考图数量自动增加人物。
8. 仅列本镜实际缺少的必要参考素材。参考模式未选择起始帧图片时，
   不得将起始帧加入缺口清单。
   同一参考板需要多个区域时，应区分实际上传方式：

- 上传整板：只登记一个槽位，在控制范围中列出所需区域。
- 上传多个裁切图：以不同的真实裁切文件分别绑定 REF。
- 仅有 PLAN 且尚无独立裁切条目时，先登记一个整板计划，
  明确需要的区域；待独立裁切素材或合法条目准备好后再拆分槽位，
  同步上传顺序和正文图号。

不得重复使用相同定位符与相同用途来表示多个独立上传素材，
不得虚构文件路径或随意更换用途绕过检查。
   
### 使用场景多视角参考

- 项目已有场景基准图、俯视结构图或多视角参考板时，逐镜选择与原冻结关键帧机位相符的单格或局部作为地理参考，并写明来源条目、所选观察方向和控制范围。

- 俯视图控制空间关系，不控制成片观察角度；多视角板控制场景外观与对应视角的可见结构，不覆盖本镜景别、人物站位、持物、遮挡和起始状态。默认不把整张九宫格作为剧情首帧构图。

- 有真实图片时绑定REF；创作者自行准备且图片未进入项目时使用PLAN。引用整板中的局部时，在控制范围中明确“第几行第几列”或具体观察方向；单格已保存为独立文件时优先引用该文件。

- 不同视图相互矛盾，或所需方向没有可靠参考时，明确记录缺口，不擅自改变剧情、镜头边界或场景布局。

## 完成

点名范围的原文都有镜头落实，每镜职责不重复、空间与状态连续、起止边界可制作、关键帧可冻结，
每镜「来源」解析到《剧本.md》的真实场景、剧本里每个场景都有镜头承载或已记入「未拍场次」，
且每镜关键帧里的可见人物、地点、道具都在本镜「视觉依据」里，即完成。画面需要、但《视觉设定.md》
还没有条目的可见物件，在末尾报告里逐项点名。本次请求同时修改
《图片提示词.md》与《分镜.md》时，当轮刷新受影响镜头的引用；不另建覆盖表。
视频提示词、生产和审查只有用户点名时开始。
写完本阶段文档后，可转 `$short-drama` 做局部机械核对（只核对已有文档）；五份齐备后再做完整核对。内容质量仍由创作者审查。
