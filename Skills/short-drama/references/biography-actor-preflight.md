# 明确人物传记：原创演员重现与形象前置验证

## 适用边界

只有用户明确将当前作品／人物定义为人物传记、名人传记，或明确要求以某位真实人物的生平为改编对象时启用。已记录的同一项目明确选择可沿用，不要求每轮重复声明。类型记录与后续入口的读取按[类型交接与事实边界](biography-context.md)执行；关键史实由叙事阶段核查，视觉阶段继承结论。

- 原创短剧、漫剧及未声明传记的请求，沿用原流程，不自动改脸、不新增前置测试。
- 仅出现真实姓名、历史背景、照片、写实画风、参考文档中的传记示例，或本技能自己的说明，不算用户选择传记。题材确实未定且会影响人物设计时，只澄清这个选择；其他工作继续。
- 在明确的传记中，仅对需辨认其真实叙事身份、拟以独立演员重现的人物执行。无名功能人物和普通群演仍按既有个人／群体准备深度处理，不逐人建板或测试。
- 本分支只决定生成形象的表达与验证，不改真实人物姓名、关系、年代、经历、赛事结果、已确认剧情、镜头、对白或集长。未明确要求时不扩大到去商标、改场馆、换配饰等其他视觉政策。

## 两层身份与单一事实来源

在现有《视觉设定.md》对应人物条目内区分：
- 叙事身份：故事讲述的真实人物；
- 重现方式：原创演员重现；
- 演员识别锚点：一张独立原创面孔，以及有来源、有时期范围的气质／造型特征；
- 形象进度：候选待测／实测待选／验证选定；与外观是否被用户喜欢分开，明确未知项；
- 验证记录：候选与提示词版本、实际图片／素材位置、平台入口及模型、模式、测试日期和实际结果，注明用户反馈或直接核看的证据来源。只记录当次有用信息，不索要凭据、虚构素材编号或另建身份数据库。

发型、胡须、体态、衣装、配饰等可表达时代与人物气质，但不为保留“神似”而复刻真人精确骨相、照片皮肤纹理或原声。不得把某一示例的白人男性、背头、胡须、戒指或足球服套到所有传记人物；儿童、青年及历史造型按自己的时期事实处理。真实照片可作已声明的年龄、职业气质、衣物或史料资料，不能因文件存在自动变为原创演员的身份模板，也不承诺相似度降低即可绕过审核或取得权利许可。

保持一个选定演员的跨镜身份，各年龄及衣装为该演员的变体。新面孔在选定前只是候选，不覆盖既有确认身份或被写成最终连续性锁；已经确认的非面部事实继续保留。用户明确要求使用已授权真人复现时尊重该新选择，并按目标入口的授权／素材要求处理，不静默套用原创演员默认。

不自动迁移旧项目、重写已确认面孔或清空已有素材。对已有选定版本，沿用其明确选择及已知测试证据；历史平台验证未知就如实记录未知，不伪称通过。用户重新设计该人物或要求补测时再处理相应范围。

## 前置配对交付

新候选尚未验证选定且本轮请求设计／确定该传记人物形象时，先交一组候选的两份完整、可复制文本，不直接扩成全套多造型详细板：

1. **图片候选提示词**由 image-prompts 负责。默认单人正面或轻偏侧中近景，身份清楚、中性光线、简单背景与一套相容造型。写清原创面孔、必要气质、发型／配饰及禁止复制的范围。若必要配饰不在取景内，不假称已验证该细节；按需要选半身而不先做拼板。
2. **验证短片提示词**由 video-prompts 负责，使用同一候选图，采用已选模型／服务及模式的合法短时长、单一连续镜头和少量自然动作。可检查轻微转头、自然呼吸、表情和必要手部细节；需要口型时可加入明确标为测试用途的中性短句或已有短对白，不将测试句反写入剧本。

两份文本同请求配对交付，说明先出候选图，再用该图实际测试视频。图片尚不存在时视频文本仍可先完整写好，但输入仅为自行挂载计划，不编造REF／文件／测试通过。实际图片存在且用途核对后再登记真实REF。未声明用图的模式不根据测试需要擅改；模型／入口确实未定时只澄清必要选择，通用内容草稿不冒充已适配接口。

尊重本轮明确范围：用户只要视觉事实且明确不写提示词时，assets 只写候选与未决项，不越界交付提示词；用户明确只要图片候选时，只交这部分并说明短片尚未测。用户允许一次交多个候选时按其范围，不固定每个人都生成三种方案。

### 与五文档及检查器的关系

- 候选事实和验证结论仍由《视觉设定.md》该人物条目维护，未提供项目文件时先在会话说明，不为普通咨询初始化项目。
- 测试图片若保存为正式图片提示词，可在现有《图片提示词.md》使用一个明确为“候选单幅”的IMG条目；ID只证明提示词存在。已生成的候选脸可继续作为后续身份依据，不为验证完成另加重复头像任务。
- 配对短片是片外制作验证，不属于剧情。默认在本轮回复中提供独立标注的测试正文；用户要落盘时可使用现有可选分析区 `项目开发/人物形象验证.md`。它是片外工作稿，不是第六份必备创作文档或另一份身份真相，不重复维护视觉设定。
- 不在正式《分镜.md》《视频提示词.md》添加虚假的SC／SHOT／MOTION／GROUP、虚构对白来源或测试时长，不为满足“每MOTION必须有SHOT”补造剧情。现有正式镜头一一对应、容器唯一计数及总长规则原样有效。
- 测试单只有一份相应可复制正文，元信息、结果与缺口放正文外；正式五文档的机械检查不被当作该短片的生成或媒体验收。没有实际IMG／SHOT条目时，测试计划不冒用正式PLAN定位符。
- 待测期间可继续剧本、调度／分镜草稿、场景、道具及其他不依赖该面孔的工作。依赖此候选的正式人物定妆扩展暂列未决，不把候选说成已确定；用户明确要预写下游文本时可按候选／PLAN写完整草稿并说明未定，不能假称形象已锁定或投产就绪。

## 真实测试与选定

图片和视频默认由创作者自行生成。写测试文本、用户说“先测试一下”或候选已被喜欢，均不自动授权模型调用、付费生产或失败重试；若用户明确委托代测，仍进入 produce 的完整预览与本次显式确认流程。当前内置选择器不因存在片外测试单就新增支持，不为调用它补造正式镜头。

三个结论分别记录，不互相替代：
1. 平台结果：指定素材在指定入口实际被接受、任务完成；
2. 制作结果：面孔、动作、必要细节及口型达到本次测试目的；
3. 创作者选择：用户选用这一候选版本。

对新进入本分支的候选，**验证选定**专指：同一候选版本的平台结果和制作结果达到测试目的，且用户选用。用户只说“选这张”时记录“外观已选，视频未测”，尊重其选择但不把该人物标为验证选定；依赖此面孔的正式详细定妆默认等待这项前置验证。用户明确要求先预写时仍可交付标为候选／待测的完整草稿。这个要求不追溯新增到前述旧项目继承身份。

用户明确反馈“这版实测成功且选定”可以作为该次记录，不要求无谓重复确认；仅有“选这张”不等于视频已通过，仅有生成成功不等于用户已选或质量合格。能够核看实际结果时补充观察，不能把文本自检、任务编号或未读文件当成像素／音频验收。未报告的项保持未知；用户要求先预写下游不改变这些事实状态。

新候选完成验证选定后回到原有规则：需要持续辨认的主角／重点人物按已选身份制作必要正／自身侧／背全身、面部及衣饰细节；功能人物、普通群演的原准备深度不变。沿同一演员展开年龄和造型，不逐镜重新造脸。

## 平台条件与复测范围

测试使用当前项目的模型、语言、模式、画幅及服务限制；不会为测试改变模型、原生时长、参考预算或生产规则。没有适用资料时不猜能否接收真人／虚拟人脸、首尾帧与参考能否混用。平台政策需核实具体入口；未要求查询或执行时不因此自动联网。

对实际使用的入口，区分授权真人素材、预置虚拟人像及平台认可的原创产物路径。不把原创脸被拦直接解释成“仍然太像”，应记录完整报错并核对合法素材路径；不通过反复改脸、伪报来源或换词寻找审核绕过方式。来源、账号、有效期、原始产物要求及裁切／转码影响均按该平台当前规则核实，不预设详细板裁出的单幅仍具有原始产物资格。

更换脸部身份、实际输入素材、平台／模型／模式／入口，或已知来源条件失效时，仅复核受影响的结论。普通衣装变化不自动推翻已选演员身份；年龄跨度或未测试的关键细节按实际需要补测。不为技能更新、改文案措辞或可用原图的未变用途重复验证，也不将某一次成功承诺为跨平台或永久可用。

## 分工与默认规则不变

| owner | 本分支负责什么 |
|---|---|
| short-drama / develop | 只在用户明确选择时记录传记类型、适用人物和后续路由；不为此强制开发文件 |
| assets | 两层身份、候选事实、验证记录及选定后的连续性；不把提示词写进视觉事实正文 |
| image-prompts | 候选单幅提示词及依赖；未选定前不直接扩全部人物板 |
| video-prompts | 片外验证短片的完整正文；正式镜头仍继承分镜、逐字对白与合法分组 |
| storyboard | 继续剧情与调度，区分候选和已选身份，测试短片不计入正式镜头 |
| review | 仅在获授权的范围审结论与证据；不把原创项目未测试列为缺陷 |
| produce | 测试也遵守现有预览—显式确认—运行，不增加自动服务调用 |

本分支不替代Look Development，不把其可选性改成全项目必经门槛；不取消语言政策、9图封顶或原生更低上限、REF／PLAN真实边界、场景空间一致性、年龄与服饰变体、正式镜头映射、对白保留或显式生产确认。
