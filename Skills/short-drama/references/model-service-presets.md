# 模型服务预设：按选择覆盖，不改变创作契约

维护日期：2026-10-28。下表统一管理本地模型选择；Seedance四档名称是创作者提供的服务档位，不是供应商官方 model ID。
本文件集中管理这些档位的差异；现有模型方言继续管理摄影、表演、声音与素材语法。
Seedance服务差异来自创作者声明；Wan 3.0沿用已有方言与已接受执行档案，不改变其原设定。

## 全模型统一参考图片上限

创作者最新要求：所有模型和服务档位，每次实际生成统一最多9张参考图片，包括图片生成、视频生成、GROUP、独立镜头及尚未列出的模型。原生、模式或已确认档案有更低上限时取更小值；首帧1张、首尾帧2张等更严格规则不变。9是本套件执行上限，不是对未知渠道支持9图的能力承诺。

按本次实际上传图片计数；同一实际文件在提交前合并上传可合并职责，不合并不同造型/状态输入。视频、音频分别计数，不占图片号，也不改变其原有限制。这不是资产库总量配额。超过9图须复核复用与必要引用或由分镜调整分组，不能丢必要参考、冒充同图、默改时长或切换文生路线。

此上限不依赖是否选择预设。旧项目原始能力声明不自动改写，实际执行取统一9图上限与原有限制的较小值；旧低价/Wan档案中合法的10图能力声明也不能放行第10张。仍拒绝超过已知原生能力的非法声明。

## 1. 何时读取与采用

初始化或继续项目，以及直接调用写作、资产、分镜、图片提示词、视频提示词、生产或审查技能时：

1. 用户明确点名下表中的服务档位，或项目已有 accepted 的 `video_service_preset`，才读取并采用对应行。
2. 比较名称时忽略大小写和普通空格；Seedance档位可省略“模型”或加 Seedance / seeddance 前缀，不靠“2.0”“便宜”“mini”等不完整名称猜档位。`Wan3.0`、`Wan 3.0`、`wan-3.0`均明确指向Wan 3.0预设。单独的 `seedance-2.0`、`seedance-2.5` 继续按原方言处理。
3. 本轮明确选择高于项目原选择；将选择按 `$short-drama` 既有创作者决策流程写入 accepted 的生产档案，后续沿用。不因安装本文件而迁移旧项目。
4. 只启用所选行。全模型9图封顶始终生效；模型专属更严格限制继续遵守，其余模型专属限制覆盖通用档位建议，项目剧情、画幅选择、语言、集长、参考生路线、身份与持物连续性继续由各自来源拥有。
5. 若新能力与项目已有硬要求冲突，先指出具体冲突并完成不依赖它的工作；不得默改项目要求或伪称适配完毕。

- Mini与标准版目前只有上述能力相同。两者独立记名，不推测速度、价格、画质、动作或身份保持能力的差别。
- 2.5严格首帧／首尾帧仅在具体入口已核对、创作者明确确认并纳入accepted的`supported_generation_modes`后启用`first_frame`／`first_last_frame`；推荐默认不声明它们。选择2.5或附尾帧图本身不启用严格帧位，也不将普通reference与严格role混用。
- Mini、标准版的原生输出时长、分辨率、画幅、输入媒体时长、组合总额和音画同轨能力未在本次声明。已有同一服务的已接受参数可以沿用；首次选择时未知项留空。不要把普通2.0方言里的4～15秒、输入总时长等默认值当作该服务已确认能力。缺值只阻止对相应生产参数作就绪承诺，不妨碍先写内容草稿。
- 低价版未声明视频/音频参考、首尾帧、编辑、延长或音画同轨能力，不从9张图片的执行上限推导这些能力。默认保留用户已经选择的参考生视频路线。
- “原生不卡脸”仅保留为创作者提供的渠道描述，不等于同脸稳定已验证，不取消人物身份参考与结果核对。
- 不把视频模型的720P输出要求套给参考图片的出图分辨率；图片生成模型与视频服务档位是两个选择。
- Wan 3.0沿用原来的2～30整数秒、中文自然指令与同轨声音设定；分辨率按项目已接受的1080P/720P/480P之一，不新增默认值。参考视频/音频每段1～15秒，各类合计不超过15秒；含视频输入时，输入视频时长加本次输出时长不超过30秒。这些均来自既有Wan方言，不据此给其他档位新增能力。

## 3. 低价版：只锁GROUP，不锁组内SHOT

这是本次更正后的最终规则，优先于此前“每镜锁5/10/15”的表述和此前“超过15秒GROUP照常生成”的设想。

- 每个正式 GROUP 总时长严格属于 `{5, 10, 15}` 秒；4、7、11、13、16、24秒等均不可提交，没有长GROUP例外。
- SHOT / MOTION 是叙事与审查单位，组内可以是4+6秒组成10秒GROUP、3+4+8秒组成15秒GROUP，或使用合理的非整数切点。
- 独立提交一个镜头时，它就是单成员GROUP，提交总时长也必须为5、10或15秒。低价版建议把这些单镜同样显式列为GROUP；没有GROUP条目时，检查器按每个MOTION独立提交核对。
- `GROUP时长 = 成员SHOT/MOTION时长之和`；每个成员只计一次，成员顺序相邻，同组不得跨场次。一次生成仍可含多个有独立职责的镜头。
- `所有正式生成单位（GROUP与独立单镜）时长之和 = 项目目标集长`。默认mixed策略下，GROUP与未归组的独立MOTION共同覆盖全集，每个镜头只计一次；已归组MOTION只作审查依据。用户明确全部采用GROUP时记录`delivery_route: groups_only`并核对全覆盖。模型选择本身不改变交付策略。
- 项目集长不因模型变化自动改动。严格直出时总长只能是5秒的整数倍；例如90秒可实现，92秒不可同时满足当前直出算术。后者列明冲突，由用户选择调整集长或另行授权“生成时长与剪辑保留时长分开”的方案，不默认超生成再裁切。
- 先核算整集，再排合法生成组；不能把各组逐个向上取整，造成总长膨胀。旧分镜若无法只靠重新分组满足，应明确提出需要调整的镜头时长/边界，交回分镜阶段；视频提示词阶段不能私改来源。
- 5秒适合内容量确实能容纳的短反应或单一动作；10/15秒可容纳较完整的对白、交接和运动过程。这是按内容量选择档位的建议，不是强制镜型配额。不能靠加速台词、删词、镜外换手或机械空等凑档位。
- GROUP参数显式写所选秒数，不用自动时长。正文、成员区间、上传清单生效区间、整集区间须同步。

## 4. 各阶段怎样适配

### 项目、剧本与视觉设定

- 路由技能保存服务预设，区分创作方言与实际执行端；真实 Endpoint / model ID 仍放项目外的执行配置，不根据档位名称编造。
- 写作按项目总时长安排真实对白、动作和停顿；场景时长不是GROUP时长，不给每场套5/10/15。已确认剧情与逐字对白不因模型约束自动改写。
- 视觉设定保持原有人物准备深度：主角及需辨认配角按身份管理；功能人物、普通群演按实际连续性需求准备。不因槽位上限增加角色、复制同脸或删掉确认人数。

### 分镜

- 先设计戏剧职责、观众获知时机、轴线、双手与持物状态，再选生成组。低价版在整集设计阶段落实本文件第3节；其余档位遵循自身已接受能力，不继承低价档位锁。
- 每组列成员镜头、累计起止秒数、总时长、组内切换和组间接点；参考数量按整组去重后的实际上传集合计算，不能只看单个成员是否超限。
- 上限是容量而非目标。超限时先复用已有单幅/局部并合并同文件职责，再评估拆组；不得删掉必要身份、关键道具或空间依据。参考不足时如实列缺口。
- 冻结关键帧只作开场构图的文字依据。用户选择参考生视频时，不为上述任何档位增加“每镜先生成首帧”的要求。

### 图片提示词

- 身份板、造型板和空间参考组仍作设计与核对材料；实际上传优先身份明确、造型正确的单人单幅、面部/服饰局部、对应机位场景单格及关键道具状态局部。
- 低价版720P下，承担辨认或因果的五官、眼镜、手持物、衣袖接触等应占足够画面比例，避免把必要细节压在过密九宫格或遥远背景里；通过取景与参考用途处理，不增造剧情或要求每件普通道具单独出图。
- 现有图可裁切满足需求时先说明范围，不新增出图任务；实际未裁切就不能登记裁切文件为REF。PLAN继续表示待自行准备的素材，不是已有文件。
- 图数预算只约束当次实际上传集合，不限制整个资产库的图片总数。不同造型状态按生效镜头分开说明，不把多视图误当多个人。
- Mini/标准版使用首尾帧路线时只准备相应1～2张；使用参考生时按9图预算准备，不把首帧/首尾帧模式与参考模式拼成未经声明的新组合。

### 视频提示词

- 低价、Mini、标准版使用既有2.0的中文摄影与表演表达、`@图片N` / `@视频N` / `@音频N`素材标记及对白/声音写法；只启用当前服务已声明的输入能力。这个方言复用不授予未声明的API能力。
- 2.0多镜正文用“镜头1、镜头2……”和明确切镜、动作先后、触发与停顿；组内累计时间仍在审查表准确保留，不声称2.0能精准执行时间戳。不能照搬2.5的时间戳控制能力。
- 2.5高级完整沿用原2.5的时间段、反应链、任务类型及真实视频续接规则，不新套低价版时长档位或720P；图片执行上限统一为9张。
- Wan 3.0完整沿用原Wan方言：素材写`图N`、`视频N`、`音频N`，多镜正文用`(0:00 - 0:03) 镜头1，…`累计时间段，对白写`说道：“逐字台词”`；不套Seedance的`@图片N`、花括号对白或2.5任务类型。保持参考生路线，不新增每镜真实首帧要求。
- 保留逐镜MOTION作为依据，每GROUP提供唯一完整可复制正文。先对整组真实输入去重并连续编号，再逐一重映射成员编号；不能直接拼接若干独立提示词。
- 每组上传表列实际顺序、类型内图号/视频号/音频号、REF或PLAN、职责、生效成员和阶段；附成员编号到整组编号映射。图、视频、音频分别编号，不能把3段音频占成3张图片。
- 参考视频只控制明确指定的动作、运镜等维度；参考音频只控制已声明的音色等维度。支持参考音频不等于台词逐字回放，也不证明本次音画同轨；声音能力未知时保留完整声音职责，不承诺同次生成。
- 对白逐字保留，先核对说话窗口和不宜重叠的动作，再写摄影、光线、表演、声音。复杂交接要写接触—承重—释放，避免用模型档位掩盖逻辑断裂。

### 审查与生产

- 审查只按本项目已选档位检查，位置、影响、建议及优先级仍按原审查契约写；不要用低价版规则误报Mini、标准、2.5或Wan项目。
- 投产前核对本次实际服务、时长、画幅、分辨率、图片/视频/音频数量与模式，不只检查提示词里写了什么。Mini/标准的9/3/3分别计数，没有本次声明之外的合计限制。
- 本文件不改变既有生产授权流程，也不新增自动提交能力。当前内置来源选择器仍不支持GROUP或参考视频提交，用户可复制GROUP到自己的工具；不能拿某个成员MOTION冒充整组。

## 5. 项目记录与换档清理

使用 `short-drama.json#/creator_authority/production_profile/choices`，沿用既有 publish / accept / set-authority 流程；不新增每集模型配置文件或第六份创作文档。

低价版已知选择示例（语言和模式仍以当前用户要求为准）：

```json
{
  "target_video_model": "seedance-2.0",
  "video_prompt_dialect": "seedance-2.0",
  "video_prompt_language": "zh-CN",
  "video_service_preset": "seedance-2.0-low-cost",
  "native_duration_seconds": {"min": 5, "max": 15},
  "output_resolution": "720p",
  "supported_aspect_ratios": ["16:9", "9:16", "4:3", "3:4", "1:1", "21:9"],
  "reference_limits": {"images": 9, "videos": null, "audios": null},
  "supported_generation_modes": ["reference"],
  "generation_mode": "reference",
  "audio_generation": null
}
```

`native_duration_seconds`的区间不能表达离散档位；检查器通过已接受的`video_service_preset`执行5/10/15规则。`multi_shot_containers`仍只记录用户是否采用多镜一生成，不由选模型自动开启。

| 字段 | Mini | 标准 | 2.5高级 | Wan 3.0 |
|---|---|---|---|---|
| target_video_model / video_prompt_dialect | seedance-2.0 | seedance-2.0 | seedance-2.5 | wan-3.0 |
| video_service_preset | seedance-2.0-mini | seedance-2.0-standard | seedance-2.5-advanced | wan-3.0 |
| native_duration_seconds | 同一服务已接受值，否则null | 同一服务已接受值，否则null | 沿用2.5既有推荐或已接受值 | 沿用Wan原设定：min:2, max:30，提交整数秒 |
| reference_limits | images:9, videos:3, audios:3 | images:9, videos:3, audios:3 | images:9；videos/audios沿用同一服务已接受值，否则null | images:9, videos:5, audios:5 |
| supported_generation_modes | text, first_frame, first_last_frame, reference | text, first_frame, first_last_frame, reference | text, reference, edit, extend | text, first_frame, first_last_frame, reference |
| output_resolution / supported_aspect_ratios | 未知则null | 未知则null | 沿用同一服务已接受值，否则null | 沿用同一服务已接受值，不继承低价720P或六画幅列表 |
| audio_generation | 未知则null | 未知则null | 沿用原2.5设定 | same_pass |

生产档案的choices写入会合并旧键。换服务时要显式清理上一服务带来的原生时长、参考上限、支持模式、分辨率、画幅能力、声音能力；未知值写null，不能只换名字留下旧服务的限制。项目已选画幅、集长、提示词语言、生成模式和多镜选择是创作要求，不能跟着清空；与新能力冲突时明确报告。

## 6. 本地校验的范围

时长正数与完整解析适用于全部文档。`creator_markdown_check.py`通过`scripts/video_contract.py`统一读取accepted模型/服务能力；明确模型的基础范围不依赖是否另外声明服务预设。检查包括：

- 低价版每个显式GROUP的5/10/15秒档位；没有GROUP时按独立MOTION核对，不量化组内SHOT。
- 根据delivery_route核对唯一计数及必要的完整覆盖，GROUP与独立MOTION总时长须等于项目集长；分镜已存在时也核对镜头总时长。MOTION不会与其GROUP重复计数。
- 已知模型原生范围和整数要求只作用于实际生成单位，Mini/标准未知能力允许草稿但执行前须确认范围与`duration_integer_seconds`精度；低价版项目画幅、档案720P及整组参考图片预算；Mini/标准和显式Wan预设的参考图片预算（所有模型实际图片输入统一最多9张）。图片数量按成员REF/PLAN定位符去重合并，并额外检查能解析的GROUP实际图片上传表，不能用成员各自未超限掩盖整组超限。

视频/音频段数、媒体本身的真实状态、图号映射语义、声音能力、实际执行参数及切点精度，仍由相关阶段核对；当前检查器不证明这些项目已经通过。分镜阶段尚无视频GROUP时，表内分组档位由分镜owner核对，不能把局部检查成功当成未来GROUP已经合格。

最小行为样例：低价GROUP7秒拒绝；10秒GROUP含4+6秒成员接受；15秒接受；24秒拒绝；按90秒项目排成104秒拒绝；Mini/标准/Wan不触发低价离散规则；Wan的7秒、24秒等合法整组时长按原设定保留；没有选择预设的原有模型行为保持不变。

## 7. 执行契约与共享实现

确定性能力判断统一由`scripts/video_contract.py`提供，生产技能通过同级目录加载它；迁移时保留short-drama与short-drama-produce的相邻关系。硬参数变更同时更新此实现及反例测试，其他阶段引用本文件，不再各自造一套时长规则。

`delivery_route`默认mixed，只有明确选择整集只用GROUP时写groups_only。`duration_integer_seconds`只用于补充已确认的服务精度，不能关闭模型原有整数要求。换档清理时同时刷新这些服务能力字段，交付策略不随模型改变。

内置官方Seedance编译器没有核对过2.0低价/Mini/标准三个渠道，不接受用渠道别名冒充官方model ID。这三档继续可完整交付手动生成文本；自动执行须使用确实实现该渠道、接受相应分辨率且已匹配的专用adapter。没有该适配器时明确不可自动提交，不默改模型、分辨率或生成模式。

视频生产参数须与来源MOTION时长、项目画幅、任务类型和已选服务一致；项目配置纳入确认指纹，改变后重新prepare。运行前读取同一能力规则，并要求外部adapter的`video_model_profile`与项目模型、服务档位及分辨率匹配。它是操作者对执行端的明确声明，不代表已实测供应商能力；仍按既有预览与确认边界执行。
